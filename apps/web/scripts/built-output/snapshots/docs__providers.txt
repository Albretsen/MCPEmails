What commonly breaks
Gmail (IMAP)
App-specific password
imap.gmail.com
993 · TLS
smtp.gmail.com
465 · TLS
The app password option does not exist on the Google account until 2-Step Verification is on, and it disappears again for everyone in a Workspace whose administrator switches app passwords off for the domain. Google shows the password in four blocks; the spaces are display only and are stripped before the login is sent.
Gmail (API)
Google OAuth
Provider API, no IMAP
Provider API, no IMAP
Nothing at the transport layer: this row talks to gmail.googleapis.com rather than IMAP. What breaks is consent. The app is not verified by Google, so the sign-in screen carries a warning you have to click past, and Google lets an unverified app be granted consent by at most 100 accounts in its whole lifetime, a counter that cannot be reset. That ceiling is why the app password above is the default way in. The limits afterwards are semantic: labels instead of folders, no native copy, and no permanent expunge.
Fastmail
App-specific password
imap.fastmail.com
993 · TLS
smtp.fastmail.com
465 · TLS
The ordinary account password is refused outright. Fastmail issues a 16-character app password, and submitting the login password instead is the most common single cause of a failed connection.
iCloud Mail
App-specific password
imap.mail.me.com
993 · TLS
smtp.mail.me.com
587 · STARTTLS
Two-factor authentication has to be on before Apple will generate an app-specific password. Apple displays that password as four hyphenated blocks; the hyphens are display only and are stripped before the login is sent.
Yahoo Mail
App-specific password
imap.mail.yahoo.com
993 · TLS
smtp.mail.yahoo.com
465 · TLS
Yahoo accepts at most 5 simultaneous connections. Its rejection text, “Incorrect username or password”, names both halves on purpose and will not tell you which one was wrong.
Zoho Mail
App-specific password
imap.zoho.com
993 · TLS
smtp.zoho.com
465 · TLS
IMAP access ships switched off and has to be enabled first. Zoho also runs six regional data centres, and paid custom-domain mailboxes live on imappro/smtppro rather than imap/smtp, so the right host depends on both region and account type.
Yandex Mail
App-specific password
imap.yandex.com
993 · TLS
smtp.yandex.com
465 · TLS
Yandex does not implement RFC 4959 SASL-IR, so the inline login form comes back as a command syntax error rather than a credential error. Both “IMAP” and “App passwords and OAuth tokens” have to be switched on, and Yandex 360 custom-domain accounts may sign in with a login name that is not the address.
Microsoft 365 / Outlook
Microsoft OAuth
Provider API, no IMAP
Provider API, no IMAP
Personal Microsoft accounts (outlook.com, hotmail.com, live.com, msn.com) connect directly. Work and school accounts are different: Microsoft’s default consent policy stops employees from approving mail permissions themselves, so the dashboard gives you a shareable approval link to send to your IT admin, who approves the app once for the whole organisation and does not need an MCP Emails account; after that everyone connects normally. A Microsoft account with no Exchange Online mailbox is refused, with a hint to connect the address over IMAP instead. Microsoft may temporarily block sending from a brand-new outlook.com account that sends in bursts, as part of its own anti-abuse checks.
Generic IMAP
Mailbox password
Your host’s settings
993 / 143 · TLS / STARTTLS
Your host’s settings
465 / 587 · TLS / STARTTLS
A port and a security mode that disagree. Choosing STARTTLS while the port stays 993 opens a plaintext socket to a TLS-only listener, and the connection just times out. Failed transports are now retried automatically on the other standard combination.
Gmail, two ways in:
a Google mailbox connects either with an app password over
imap.gmail.com
, which is the default, or by signing in with Google, which uses the Gmail API instead of IMAP. Both are offered in the connect window and both keep working. The choice decides what the agent can do afterwards, so the capability table below has a column for each:
Gmail (IMAP)
for the app password and
Gmail (API)
for Google sign-in.

Login mechanism:
most servers take

Other hosts:
IONOS, Hostinger, OVH, OVH Hosted Exchange, DreamHost, Titan Email, Namecheap Private Email, Migadu, InMotion Hosting, OpenSRS, GMX and mail.com are recognised from the address or the mail host you type, and their hosts, ports and transport security are filled in for you.

Compatibility profiles
Every inbox reports a versioned profile to an MCP agent:
exact
means the normalized operation keeps its meaning,
different
means the provider uses documented alternative semantics, and
unavailable
means MCP Emails will not silently weaken the request. Profiles describe connector behavior without inspecting or storing mail.

Gmail folders vs labels:
Gmail uses a flat label system rather than hierarchical folders. "Move" is implemented as label add/remove. Native copy is not available via the Gmail REST API. These Gmail rows describe the Gmail API connector: a Gmail mailbox connected with an app password over IMAP follows the IMAP columns instead, copy included.
Outlook (Microsoft Graph):
search uses KQL. A text criterion (from, to, cc, subject, body, text or query) cannot be combined with the unread, has_attachment, flagged or date filters: when both are sent, those filters are not applied and the result says which were dropped, while a tool that acts on every match refuses the combination instead. Outlook has folders, not labels, so the label tools are Gmail-only; an automation's label action applies an Outlook category. Attachments: up to 10 MB per message when sending, and up to 25 MB when downloading an attachment or forwarding an original.
Permanent delete:
the Gmail API moves a deleted message to Trash and does not expose permanent expunge. Microsoft Graph does: permanent: true on an Outlook inbox uses its permanentDelete, which skips Deleted Items. Every IMAP inbox (Gmail on an app password, Fastmail, iCloud, Yahoo, Zoho, Yandex, Generic) supports both trash and hard expunge.
Contact search (live scan):
All providers support
contact_search
, which finds matching correspondents with a live, header-only scan of a recent window of your matching mail. There is no contacts table: nothing is stored between calls, and counts reflect only matched messages in the scanned window.
Scheduling:
Supported for all providers via a server-side
scheduled_sends
queue. Use the
schedule
tool's
create
,
list
, and
cancel
actions. Delivery uses each provider's existing send path, so no provider-native scheduling API is required.
Signatures:
A per-inbox signature is appended server-side on every send, reply, forward, draft, and scheduled message. This works on
all
providers. Signatures support rich HTML formatting (bold, italic, headings, lists, colors, alignment, links) and a hosted logo/image; set them in the dashboard rich editor or via the
signature
MCP tool (which accepts
signature_html
). Images are referenced as hosted https URLs and render across every provider, though some clients (e.g. Gmail) may hide them until the recipient clicks "display images", which is normal for any hosted-image signature. Use
signature_reply_mode
to control whether the signature appears on replies and forwards. Per call, pass
include_signature: false
on
email_compose
or
draft
to skip it. The same inbox panel in the dashboard also has a Sender name field, the display name recipients see next to the address on everything the inbox sends.
Forwarding:
On every provider a forward relays the original message byte for byte: its HTML, inline images, attachments and MIME structure arrive exactly as they were sent, under your note and the usual forwarded-message header. Originals up to 25 MB.
as_attachment
sends the whole original as a .eml part instead, and
include_attachments: false
leaves attached files behind.
