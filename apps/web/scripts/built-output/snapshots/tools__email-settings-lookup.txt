IMAP and SMTP settings lookup
Find the IMAP and SMTP settings for any email address. Type an address, a domain or a mail server name and the lookup returns the incoming (IMAP) and outgoing (SMTP) server, port and security setting. For an address on a company domain it reads the domain's MX records to show which provider actually runs the mailbox.

What these settings mean
Every mail app and connector asks for the same six values. Here is what each one does.
IMAP is for reading, SMTP is for sending
IMAP (Internet Message Access Protocol) lets an app read your mailbox where it lives: folders, read and unread flags and moves stay in sync with webmail and your phone. SMTP (Simple Mail Transfer Protocol) is how an app hands a new message to your provider for delivery. A mailbox needs both, and they often run on different servers, such as
imap.gmx.net
and
mail.gmx.net
.
Ports and security
The port and the security setting go together.
SSL/TLS
(also called implicit TLS) encrypts the connection from the first byte, on port 993 for IMAP and 465 for SMTP.
STARTTLS
connects on port 143 or 587 and then upgrades to encryption. RFC 8314 recommends implicit TLS for both reading and sending. A port paired with the wrong security setting usually ends in a timeout or a vague TLS error, not a clear message.
Your username and password
The username is almost always your full email address. The password is where most failed connections come from: Gmail, iCloud, Yahoo, AOL, Fastmail and Yandex refuse your normal account password from a mail app and want an
app password
instead, and Zoho does too once two-factor or single sign-on is turned on. Personal Microsoft accounts accept neither and need Microsoft sign-in.
Custom domains and MX records
An address on your own domain says nothing about where the mailbox is. The domain's MX records do: they name the servers that receive its mail, and that server's owner almost always runs the IMAP and SMTP servers too.
aspmx.l.google.com
means Google Workspace,
*.mail.protection.outlook.com
means Microsoft 365,
aspmx1.migadu.com
means Migadu. When the MX points at a spam filter, the mailbox host is hidden behind it and you need to ask whoever manages the domain. The
custom domain guide
walks through the common hosts.
How this lookup works
It checks, in order: the
provider settings
MCPEmails verified by connecting to each server; a table of hosting providers built from real connection failures; the domain's own RFC 6186 service records; its MX records, matched back to those tables; and Mozilla Thunderbird's autoconfig database. It shows a result only when both the IMAP and the SMTP half were found. The provider settings are also published as an open
dataset
.

Questions
How do I find the IMAP and SMTP settings for my email address?
Type the address into the lookup above. For a provider address such as @gmx.net or @yahoo.com it returns the provider's IMAP and SMTP servers, ports and security straight away. For an address on your own domain it reads the domain's DNS records to find which provider runs the mailbox and returns that provider's settings. If nothing is found, the MX records it shows tell you who receives the domain's mail, which is who to ask.
What are the SMTP settings for OVH Hosted Exchange (ex4.mail.ovh.net)?
Outgoing mail uses the same numbered host as incoming, for example
ex4.mail.ovh.net
, on port 587 with STARTTLS. IMAP is on that host at port 993 with SSL/TLS. Port 465 does not answer on Hosted Exchange, so settings copied from OVH's shared hosting (
ssl0.ovh.net
, port 465) hang until they time out. The number in the host name is specific to your service and shown in the OVHcloud Control Panel. More on the
OVH page
.
What are Purelymail's IMAP and SMTP settings?
IMAP is
imap.purelymail.com
on port 993 with SSL/TLS, and SMTP is
smtp.purelymail.com
on port 465 with SSL/TLS. The username is the mailbox's full email address. Setup notes are on the
Purelymail page
.
Should I use port 465 or 587 for SMTP?
Use whichever your provider documents. Port 465 encrypts from the start and is what RFC 8314 recommends; port 587 starts in plain text and upgrades with STARTTLS. Many providers offer both. What matters is pairing each port with its own security setting: 465 with SSL/TLS, 587 with STARTTLS.
The settings are right but my password is rejected. Why?
Many providers refuse your normal account password from a mail app. Gmail, iCloud, Yahoo, AOL, Fastmail and Yandex want an
app password
, which you create in the account's security settings, and so does Zoho once two-factor or single sign-on is turned on. Personal Microsoft accounts stopped accepting passwords from mail apps on 16 September 2024 and need Microsoft sign-in.
Can this tool test my login?
No. A web page cannot open an IMAP or SMTP connection, and you should not type a mailbox password into a lookup page anyway. MCPEmails tests the IMAP and SMTP login when you
connect a mailbox
to your AI assistant, and tells you which half failed.
