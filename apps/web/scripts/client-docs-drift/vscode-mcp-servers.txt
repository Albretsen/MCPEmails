Add an MCP server when your agent needs a capability its existing tools don't provide, such as querying a database or retrieving information from an external service. Model Context Protocol (MCP) connects agents to these tools and data sources. If your existing tools meet your needs, you don't need another server.
This article takes you from adding a server to verifying its first tool call. Choose your starting point:
I have a server URL or command: Connect a server .
Help me find a server: Choose a server to try .
My server is configured but isn't working: Check the connection .
Before you start
Enable AI features and open a local project folder in VS Code.
Check the server publisher's prerequisites. A remote HTTP server can require an account or sign-in. A server launched by a command needs its runtime installed on the machine that runs it.
Caution
Local MCP servers can run code on your machine, and tools can access external services using your permissions. Review the publisher, command or endpoint, and requested access before installing or starting a server. Only trust configurations you have reviewed. Learn about MCP server trust .
Choose a server to try
For a concrete local example, use the Playwright MCP server . It requires Node.js 18 or newer , with npx available. Check your installation in a terminal:
node --version
npx --version
The walkthrough uses Playwright to demonstrate connecting an external tool provider. For everyday browser interaction, try the built-in browser tools first: they don't require an MCP server.
To try a remote documentation server instead, follow the Context7 setup requirements for its current authentication requirements and service limits. Use the HTTP endpoint https://mcp.context7.com/mcp in the connection steps below. A remote server doesn't require a local Node.js installation.
Connect a server
Use the publisher's URL or launch command. For the Playwright example, use the command in step two.
Open the Command Palette ( ⇧⌘P (Windows, Linux Ctrl+Shift+P ) ) and run MCP: Add Server .
Choose the option that matches what the publisher provides:

For Playwright, choose Command (stdio) and enter:
npx -y @playwright/mcp@latest
Enter a server ID, such as playwright or context7 , that isn't already used in the destination configuration. Use distinct IDs for different servers you plan to use together.
For a personal configuration, select Global , and then Copilot Global when prompted. This stores the server outside your project. For team configurations or other harnesses, choose a configuration destination .
If Copilot Global isn't available, check the Copilot harness requirements before continuing with this walkthrough.
Review any server trust or authentication prompts before accepting them. Follow the publisher's sign-in instructions if the service requires authentication. Do not paste credentials into chat or commit them to your project.
You can also start the guided flow from Chat: Open Customizations > MCP Servers > Add Server . The editor is scoped to the selected agent harness.
For other ways to add a server, see Find another server .
Verify the first tool call
Adding a configuration isn't proof that the agent can use the server. Complete a request and inspect the tool call:
In the agent session, enter a prompt that explicitly names the server and a low-impact action. For Playwright:
Use the Playwright MCP server to open <your URL here> and report the page title. Use its tools, not the built-in browser tools. Do not change files.
For Context7:
Use the Context7 MCP tools to look up the React documentation for useState. Summarize the basic usage and cite the documentation returned by the tool. Do not change files.
Review startup, sign-in, and tool approval requests as they appear. Approve only actions you understand.
Expand the tool call in the conversation. Check that it belongs to the server you added and inspect its returned output.
Your connection works when all three checks pass:
A tool from the intended MCP server was called in your session.
The tool returned the requested page or documentation without a connection error.
The agent's answer reflects that tool output. A plausible answer alone isn't sufficient.
To control available tools in a Copilot session, open Chat: Open Customizations > Tools . For Local harness sessions, use Configure Tools in the chat input. See Manage available tools for the differences.
Find another server
Use the MCP server gallery (Preview) to browse publishers and capabilities:
Open the Extensions view ( ⇧⌘X (Windows, Linux Ctrl+Shift+X ) ) and search for @mcp .
Select a server and review its publisher, capabilities, and installation requirements.
Select Install for a personal installation, or right-click and select Install in Workspace to share its configuration with the project.
Complete the publisher's setup, and then verify a tool call .
If the gallery isn't available, use a publisher-provided URL or command with MCP: Add Server . Your organization can restrict which servers are available.
You can also open the gallery with MCP: Add Server > Browse MCP Servers... . Choose Add from another application... in the same picker to discover existing server configurations .
Add from a package or Docker image (model-assisted)
If you have a package or image name instead of a launch command, use model assistance to generate the server configuration:
Run MCP: Add Server and select NPM Package , Pip Package , or Docker Image .
Choose a configuration destination , then enter the package or image name when prompted. For example, enter @playwright/mcp for NPM Package .
Review the package name, version, and publisher shown in the confirmation. Select Allow only if you trust the source, then follow the model-assisted setup prompts.
Confirm a server ID that isn't already used in the destination configuration. Review the generated command, arguments, and credential requirements before accepting any server trust or tool approval prompts.
Verify a tool call from the added server.
These options appear only when model-assisted setup is supported in your current configuration. If they aren't available, use the publisher's launch command with Command (stdio) . Runtime prerequisites still apply: generating a configuration doesn't replace installing the required runtime.

Portable files use a top-level mcpServers object. The VS Code format uses servers . Don't copy a configuration between them without checking the format and capability reference .
Important
Portable configurations don't support VS Code input variables or environment files. Servers requiring interactive inputs aren't forwarded to Copilot harness sessions. Use the authentication guidance for your configuration , rather than adding unsupported credential placeholders.
To reuse an existing setup from other applications, see automatic discovery . For Dev Containers or command-line installation , follow the environment-specific instructions.
Use context and prompts from your server
Servers can provide more than tools. Available capabilities depend on the server and your session:
Resources: attach server-provided data to a request from Add Context > MCP Resources , or run MCP: Browse Resources .
Prompts: use a server's prompt template by typing /<server>.<prompt> in chat.
MCP Apps (Experimental): supported servers can display interactive forms or visualizations in chat. See MCP Apps support .
